# MOAMOA-63 최종 통합 검증

## 원인과 해결

- **카드 4개:** 카드 300px, gap 40px를 모든 화면에서 고정했다. 이전 1600px 테스트에서 부모 컨테이너는 1500px, 좌우 패딩은 각각 약 66.67px, 테두리는 0px, 목록은 1366.69px였다. 5개에 필요한 1660px보다 작으므로 4개만 완전히 보였다. `flex-shrink: 0`은 정상 동작 중이었다.
- **세로 스크롤:** Figma 고정 높이와 여백을 유지한 상태에서 이전/다음 버튼을 별도 하단 행으로 배치해 높이가 약 1160px까지 증가했다. 이제 이동 버튼을 나가기 버튼과 같은 행에 두고, 데스크톱에서는 Header 아래 상점 영역을 가용 너비·높이에 맞춰 비례 축소한다. body overflow를 숨기지 않는다.
- **가로 스크롤:** 전체 8개 목록의 원본 폭은 2680px다. 목록 내부의 가로 이동은 필요하며 overflow-x:auto, nowrap, 숨긴 스크롤바, overscroll-behavior-x:contain을 적용했다. 별도 테스트 브라우저에서 수정 전 페이지 전체 가로 넘침은 재현되지 않았으므로 그 원인을 확정하지 않는다. 최종 검증에서는 모든 테스트 너비에서 페이지 가로 넘침이 없다.
- **성공 알림:** 이전에는 단일 문자열 상태만 설정하고 종료 타이머가 없었다. 이제 성공 거래마다 고유 ID를 가진 객체를 생성하고, 같은 알림 컴포넌트를 해당 ID로 마운트한다. 컴포넌트는 5000ms 타이머와 cleanup을 소유한다. 일반 리렌더링은 타이머를 재설정하지 않고, 새 거래·언마운트는 이전 타이머를 정리한다.

## 레이아웃 정책

데스크톱 기준은 CSS 너비 1024px 이상, 높이 600px 이상이다. Header는 변경하지 않고 기존 176px 영역을 유지한다. 상점의 1920×904px 기준 영역에 `min(1, viewportWidth/1920, (viewportHeight-176)/904)` 배율을 적용한다. CSS zoom을 사용해 카드·간격·이미지·텍스트·버튼을 함께 축소하며 CSS transform이나 blur는 사용하지 않는다.

1920×1080에서 컨테이너 1820px, 패딩 80px, 내부 목록 1660px, 카드 300px, gap 40px를 유지한다. 판매 컨테이너는 제공된 상점_판매완료.svg의 659px를 반영하고 하단 여백을 조정하여 판매 화면도 1080px 안에 맞춘다.

| ---------- | -------------: | -----------------: | ------------------------------ |
| 1920×1080  |          300px |                  5 | 없음 / 없음                    |
| 1536×864   |    약 228.31px |                  5 | 없음 / 없음                    |

검증은 개발자 도구를 열지 않은 별도 Edge 테스트 인스턴스에서 지정한 CSS 뷰포트로 수행했다. 사용자가 열어 둔 IDE 브라우저의 실제 현재 크기는 연결 도구로 직접 읽지 못했다. 846×219를 평소 화면 크기로 간주하지 않았다. DPR 1 및 1366×768 / DPR 1.75를 별도로 확인했다.

## 성공 알림 디자인과 검증

직접 확인한 자료:

- design-reference/modals/구매완료모달.svg
- design-reference/modals/상점_판매완료.svg
- 구매완료모달(1).svg는 로컬 프로젝트에서 찾지 못했다.

구매완료모달.svg의 실제 내용은 판매 완료 알림이다. 구매 알림에도 같은 시각 구조를 사용하고 사용자가 지정한 구매 문구를 적용했다.

리본 판매 알림의 최종 브라우저 측정:

- 외곽: X684.5, Y164, 551×94px
- 실제 캡슐: X704.5, Y179, 511×54px, radius 27px
- 브라운 #3B2F26, Jua, 원본 필터에 대응한 그림자
- 독립 요소 순서: 메시지 span → 기존 coin.svg img(28×28px) → 금액 span
- 구매 −가격 / 판매 +가격, 이/가 공통 helper 적용

브라우저 시계를 제어한 검증:

- 구매: 밀짚모자가 성공적으로 구매되었어요! / −500
- 판매: 리본 헤어핀이 성공적으로 판매되었어요! / +400
- 구매: 천사 링이 성공적으로 구매되었어요! / −600
- 4000ms 및 4999ms 표시, 5000ms DOM 제거
- 탭 전환 리렌더링 후에도 원래 생성 시점에서 5초
- 같은 아이템의 판매 후 재구매: 이전 타이머 취소, 최신 거래부터 5초
- 알림 종료 후 잔액·인벤토리 유지
- 상점 나가기 → / 이동, 언마운트 후 알림 없음
- 잔액 부족 거래는 구매 차단, 새 성공 알림을 생성하지 않음

실제 시간 검증도 별도로 수행했다. DPR 1.75에서 구매 후 4초에는 알림이 존재했고 약 5.1초에는 제거됐다. 당시 잔액 500은 유지됐다.

## 픽셀아트 보존

기존 items 및 items-large SVG는 삭제·덮어쓰기하지 않았다. 큰 버전도 임베드 PNG 해상도·SHA-256이 기존과 동일했다. 기존 렌더링용 items/pixelated SVG 복사본을 유지한다. 복사본은 원본 PNG와 viewBox를 그대로 사용하고 소수점 pattern/use 변환을 제거하며 내부 image와 바깥 이미지 모두 pixelated를 적용한다.

모든 SVG 로딩과 원본 PNG 바이트 동일성을 재검증했다. 이미지 표시 영역 160×160px, 원본 비율 유지(object-fit:contain)는 그대로이며 데스크톱 비례 축소만 적용한다. 정수 배율로 강제하면 지정 크기가 바뀌므로 강제하지 않는다.
